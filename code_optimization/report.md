# Code Optimization Report: 枢纽行人仿真 step() 向量化

## Baseline Performance

- Implementation: `animate_transfer_env.py` 原始 `HubTransferAnimator`（冻结副本：`code_optimization/baseline_animation.py`）
- 热点：`_local_density()`（n 次 O(n) 循环）、`_social_repulse()`（每 agent 一次 O(n)）、`congestion_index()`（n 次 O(n)）
- Input size: 44 人 × 1000 帧（默认）；500 人 × 300 帧（扩展性）
- Baseline time: **0.68 s**（默认）/ **7.16 s**（大规模）
- 内存：O(n²) 距离矩阵为 v1/v2 引入（500 人时约 2 MB float32，可忽略）

---

## 【优化版本】v1

### 【优化内容】
1. 每帧一次性计算成对距离矩阵 `dist`（`einsum` 优化），`_local_density` 改为单次掩码求和
2. 社会力改为矩阵运算：`inv = 1/(dist+ε)` 掩码化后 `einsum("ijk,ij->ik")` 聚合，替代每 agent 的 Python 循环
3. 原因：消除 n 次 Python 层 O(n) 扫描，把 O(n²) 下沉到 NumPy C 层

### 【优化后性能】
- 运行时间：0.68 s → 0.45 s（默认）；7.16 s → 6.77 s（大规模）
- 性能提升：1.53x / 1.06x
- 结论：默认规模有效；大规模下瓶颈转移到**逐 agent 的 Python 主循环**（墙体斥力、噪声、速度、投影都是逐元素操作），单纯矩阵化收益消失

### 【和标准库对比】
- 验证结果：到达人数与基线一致（统计等价）

---

## 【优化版本】v2（最终采用，已移植进 `src/zhishuxing/core/animation.py`）

### 【优化内容】
1. **全 step 向量化 + 活跃集压缩**：仅对“已放行且未到达”的 agent 子集计算（`np.where` 活跃索引），已到达/未放行者零开销
2. **墙体斥力广播**：11 块墙 × m 个活跃 agent 的最近点/斥力一次广播算完，替代逐 agent × 逐墙循环
3. **阶段目标查表**：`_stage_targets[i, s]`（n × 4 × 2）在 `__init__` 预构建，替代每帧逐 agent 的路线字典查找；类型速度加成同为查表
4. **批量噪声/速度采样**：`rng.normal(size=(m,2))` 一次生成
5. 罕见路径（墙体投影回退、卡滞引导介入）保留小 Python 循环，不拖累主路径
6. `congestion_index()` 同步向量化

### 【优化后性能】（3 次重复取最小值）
- 默认规模（44×1000）：0.68 s → **0.04 s**，**19.25x**（v2 独立实现 19.53x，与移植版一致）
- 大规模（500×300）：7.16 s → **0.82 s**，**8.69x**
- 内存：新增 O(n²) float32 成对矩阵（500 人 ≈ 2 MB）+ O(n×4×2) 目标查表，可忽略

### 【和标准库对比】
- 统计等价性校验（同 seed）：
  - 到达人数 `reached`：与基线**完全一致**（两种规模均 equal）
  - 引导介入次数偏差：4 / 24（轨迹微小分叉的二阶效应）
  - 拥堵指数偏差：0.0455 / 0.0
- 语义差异（已在代码注释与报告中声明）：社会力由“就地更新的位置”改为“帧首快照位置”计算——群体仿真标准做法，力场模型、速度公式、放行窗口、卡滞介入阈值（>18 帧）等所有数值规则逐行保留

### 和标准库对比（相对 NumPy 逐调用的朴素写法）
- 朴素 NumPy（v1）受限于 Python 主循环，大规模几乎无收益（1.06x）；v2 通过消除主循环取得数量级提升

---

## 最终总结

- 最佳版本：**v2**（达到 >10x 加速的提前收敛标准；总迭代 2 轮，已达上限）
- 总体性能提升：默认规模 **19.25x**，大规模 **8.69x**
- 迭代次数：2 轮（v1 算法下沉 → v2 全步向量化+活跃集）
- 优化策略：成对距离矩阵 einsum、墙体斥力广播、阶段目标/类型加成查表、活跃集压缩、批量随机数采样
- 适用场景：行人/Agent 微观仿真的逐帧推进；规模越大收益越大（44 人 19x，500 人 8.7x——大规模下 O(n²) 矩阵本身开始成为地板）
- 权衡考虑：轨迹与原实现非逐位一致（快照力场 + 批量采样），以统计等价性验收；如需逐位复现可用 `baseline_animation.py`
- 进一步优化建议（未实施）：空间哈希网格邻居检索可将 O(n²) 降至 O(n·k)，在 5000+ 人规模下会继续有效；当前规模下收益不抵复杂度
